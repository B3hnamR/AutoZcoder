# AutoZCoder 2.0.13

Full ZCode 4.0.0 desktop-client parity for the coding-plan wire format.
Based on a live MITM capture of the installed 4.0.0 client (Electron 44.7.0)
on 2026-11-23; artifacts in `D:\JB\Zcode\zcode-mitm-500m\flows-glm54`.

## Fingerprint

- Client version and UA are `4.0.0` (`ZCode/4.0.0 ai-sdk/provider-utils/4.0.27
  runtime/node.js/24`). Shipped 3.14–3.18 pins are re-pinned on load.
- `anthropic-beta: mid-conversation-system-2026-04-07` is now a static header on
  every turn; 4.0.0 no longer scopes it to GLM-5.4.
- Messages carry no `x-device-mid`; the saved device id moves into
  `metadata.user_id` (`{"device_id","account_uuid","session_id"}`).
- The bootstrap output-style block is the captured 4,721-byte document, and the
  harness bullet about mid-conversation system turns matches 4.0.0.

## Body

- Caller `role: system` turns stay inside `messages` (mid-conversation system)
  instead of being merged into the third system block. Existing native bootstrap
  blocks are still preserved without duplication.
- Image blocks are followed by the captured `[Image: source: ...]` marker, and
  the newest user turn's last block is marked `cache_control: ephemeral`.
  `upstream.anthropic_cache_control` now actually reaches the body builder.

## Limits

- GLM-5.4 advertises the captured 1,048,576 context window and accepts up to
  131,072 output tokens; the default stays 128,000 because that is what the
  desktop app sends.

## Unchanged

Tool inventory and workspace-context blocks are still caller-supplied rather
than injected, and the quota endpoint keeps being polled server-side (the
4.0.0 host process bypasses `network.httpProxy` for it).
