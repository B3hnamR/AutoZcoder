# AutoZCoder 2.1.0

AutoZCoder now serves GLM-5.4 and GLM-5.3-Flash. This release also includes the ZCode 4.0.0 request-format update and the reliability fixes made since 2.0.12.

## Models and quotas

- Added GLM-5.4 to the OpenAI and Anthropic APIs, with vision and reasoning support. The default request limit stays at 128,000 output tokens. GLM-5.4 requests are clamped at 131,072.
- Removed plain GLM-5.3 from inference, quotas, dashboard controls, relay options, and client setup. Requests that name it return an unknown-model error. Existing defaults and fallback entries that used it migrate to GLM-5.4. Retired aliases and relay selections are dropped.
- Quota parsing recognizes model capabilities, display names, and known legacy entitlement IDs. Retired buckets are excluded from active totals. Pending grants stay protected during purge.

## Compatibility and reliability

- Updated the request format for ZCode 4.0.0, including the Anthropic beta header, mid-conversation system messages, and image source labels. The cache option controls the automatic cache marker on the latest user turn.
- Fixed native Anthropic session affinity, account rotation on invalid SSE requests, truncated tool calls, fallback on quota errors, and readiness while the upstream circuit breaker is active.
- Protected newer saved credentials during desktop import and preserved persisted model caps when account inventory cannot be loaded.
- Tied Windows staged updates to the advertised release, allowed a fresh download after a failed checksum check, and blocked Apply during active inference. Graceful shutdown drains queued usage writes.
- Hardened Linux uninstall and preserved configured account and SQLite paths in backups, including committed WAL data. Preserved existing remote-admin settings, and protected worker exports and generator data from destructive cleanup.
- Fixed the dashboard's keyboard confirmation, client configuration snippets, and authentication timers. Settings and startup use the same public-bind checks. Relay health checks require HTTPS and disable redirects. The bundled Netlify relay rejects streaming requests explicitly.
- Saving the account selection strategy in Settings now applies to the live pool instead of reporting a required restart.
- Omitting the client key is limited to verified loopback peers; requests from other addresses must present one.
- Importing a JWT older than the credential already saved for that account returns 409 instead of replacing the newer token.
- The daily claim scheduler starts with the gateway when enabled, and a registration receipt is written only after the account passes its final checks.
- The Windows launcher honours `--config` and `ZCODE_GATEWAY_CONFIG` before bootstrap, and generator data is stored under the writable data root.
- The Accounts tab can copy every working account as a single bundle, excluding dead, exhausted, cooling and expired accounts, and Import account accepts that bundle directly.

## Upgrading

Existing Windows configuration, accounts, and usage data can be kept. Fresh configurations default to GLM-5.4 for Anthropic requests and GLM-5.3-Flash for OpenAI requests. Adjust clients that explicitly request the retired GLM-5.3 ID.

Linux installs created before the uninstall ownership marker was introduced may require reinstalling with the current manager before uninstall can remove the installation directory.
