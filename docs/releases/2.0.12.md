# AutoZCoder 2.0.12

Addresses upstream 405/code 3012 "This client is not supported" responses by
aligning the bootstrap system text, headers and version with the installed
client. Regression tests check exact bootstrap text; they do not establish
the server's matching rules.

## Upstream

- Bootstrap identity and harness preserve the captured official-client text,
  including the leading space on every `# Harness` bullet. Live requests returned
  200 on GLM-5.3 and GLM-5.3-Flash using a pool with 16 ready accounts and retries;
  this was not an independent acceptance test of all 16 accounts.
- Caller system text is folded into the client's third system block instead of
  appending a fourth block, matching the captured client structure.
  The harness and style blocks carry the client's `ephemeral` markers.
- Headers follow the current client: `accept-language: *`, `sec-fetch-mode:
  cors`, `x-zcode-query-source: main_turn`; the static
  `anthropic-beta: mid-conversation-system-2026-04-07` is gone (the client now
  sends it only when it really injects a mid-conversation system message).
- Fingerprint default and plan-check version are 3.18.2. Matching legacy
  version/User-Agent pairs, including 3.14.4 and 3.18.0, are normalized when
  loading the configuration. This does not rewrite the saved YAML file.
  Custom User-Agent strings are left alone.

## Diagnostics

- The "client is not supported" answer is no longer read as per-account abuse:
  it parks the model for 120 s (not 900 s) with reason `CLIENT_NOT_SUPPORTED`
  and keeps the upstream message. A stale build now says so instead of parking
  the whole pool for 15 minutes.

## Reliability

- Preserve Unicode line separators inside SSE JSON payloads, and allow the
  automatic captcha strategy to fall back when lazy OCR initialization fails.
- Keep quota-exhausted accounts retired during transient failures, reset strike
  budgets on credential replacement or explicit enable, and preserve account
  state during background upserts. Explicit add, import and login revive accounts.
- Deduplicate edge-block notifications per episode and repeated notifications
  even when older entries have been refreshed; retain unused fresh captcha tickets.
- Handle non-ASCII update-probe headers without a health-check exception.
- Shut down the previous generator and scheduler on location changes, move
  blocking stop/checker operations off the event loop, and synchronize job-map
  snapshots and removals. Disabled capture no longer deep-copies request bodies.
- Validate proxy verification intervals, reject ambiguous leading-zero proxy
  addresses, and avoid passing portless proxies to Chromium.
- Avoid retrying the same failed relay within one request, reread relay settings
  after read failures, and accept a single model name in relay options.
- Use per-account device IDs and client timezones in generator telemetry and
  exports, continue batches after individual account failures, and tolerate
  undecodable proxy-pool comments.
- Make GUI config replacement atomic and prevent pending restarts or startup
  work from overriding Stop. Drain smoke-test usage writes before closing storage.

## Upgrade

- Restart the gateway. Legacy fingerprints matching the recognized User-Agent
  format are migrated on load. Custom fingerprints require manual review.
- `docs/troubleshooting/UNUSUAL-ACTIVITY.md` documents the two 3012 variants
  and what the harness must match.

## Validation notes

- Live checks using a legacy 3.18.0 configuration migrated its fingerprint on
  load; they do not demonstrate upstream acceptance of an unchanged 3.18.0 client.
- Passing source CI does not establish packaged-build or live-provider
  acceptance. The release workflow separately requires Windows and Linux tests,
  browser checks, packaged startup smoke checks and asset checksum verification.
