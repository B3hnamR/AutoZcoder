# AutoZCoder 2.1.4

Full UI internationalization (English / Persian-FA) and RTL support across the dashboard,
a colloquial Persian version of the in-app Guide, a bundled Vazirmatn font, and the fix
of several JavaScript syntax defects that had shipped broken.

## i18n / localization

- New `zcode_gateway/dashboard/assets/js/core/i18n.js` module: a flat `en` / `fa`
  dictionary, a `t(key, vars)` translator with `{var}` interpolation and a three-level
  fallback chain (`current lang → English → raw key`), plus `lang()` / `setLang()` /
  `applyLang()` helpers. The language is persisted in `localStorage` and auto-detected
  from the OS/browser on first run.
- All 16 dashboard views are now routed through `t()` for user-facing strings:
  `accounts`, `accounts-jwt`, `analytics`, `auto-generate`, `claim-batch`,
  `generator` (+ `mail`, `setup`, `batch`, `plan`, `invite`, `claim100`,
  `claim500`, `claimstart`, `captcha` sub-views), `guide`, `logs`, `models`,
  `proxy` (+ `relays`, `sources`), `server`, `settings`.
- New **colloquial Persian Guide content** in `guide-content-fa.js` (280 lines) —
  a drop-in replacement for the English `guide-content.js`, with the same `GUIDE`
  chapter structure and `ERRORS` index. The existing `guide.js` view now picks
  `GUIDE_FA` / `ERRORS_FA` when the active language is `fa`, and re-renders on
  language switch via the `applyLang` walker.
- A language switcher (🌐 EN / 🌐 FA) was added to the dashboard top bar.

## RTL / fonts / CSS

- RTL mode for the FA language is applied through `base.css` and `components.css`
  (new RTL blocks appended; no legacy overrides removed) — `dir="rtl"` propagation,
  mirrored layout helpers under the `.rtl-fa` body class, and directional-safe
  properties. No visual regression in EN mode.
- The **Vazirmatn variable font** is bundled locally at
  `fonts/vazirmatn-vazir-woff2/Vazirmatn-Variable.woff2` so the frozen exe works
  offline with no CDN dependency.

## Bug fixes

- **`generator/mail.js` — two syntax defects that had shipped broken:**
  1. Inside `saveCfToken`, the "pending" and "failure" `setMsg` calls were missing the
     ternary `?`, so the success / pending / failure branches were mis-parenthesized.
  2. Inside `testTransport`, `showToast(...)` had an extra closing paren.
- **`generator/setup.js` — unbalanced braces in `refresh()`'s `finally` block:**
  the `if/else` chain had one too many closing `}`, making the whole file
  syntactically invalid. Fixed.
- **7 missing i18n keys** (`mail.enter_token_first`, `mail.token_saved`,
  `mail.token_saved_pending`, `mail.token_not_saved`, `mail.token_removed`,
  `mail.token_not_removed`, `mail.token_remove_failed`): these underscore-style keys
  are used by `mail.js` but were absent from `i18n.js` (only the dot-style
  `mail.token.*` keys existed). When a key is missing, `t()` returns the raw key
  string, so six Playwright tests failed with "Element not found". Added to both
  the EN and FA dictionaries.

## Version / build

- `zcode_gateway/config.py` `CURRENT_ZCODE_CLIENT_VERSION` reverted to **`4.0.0`** —
  the ZCode client fingerprint version the protocol and relay code is built against.
  (An accidental `4.1.0` bump in the i18n commit would have made ZCode see a
  non-existent client build.)
- `__version__` bumped 2.1.3 → **2.1.4**; `scripts/packaging/exe_version.txt`
  `filevers` / `prodvers` / `FileVersion` / `ProductVersion` all updated to
  `2.1.4.0` to satisfy the release-workflow tag/version validation.

## Tests

- All 55 dashboard Playwright tests pass (`test_dashboard_review_fixes.py`,
  `test_pro_dashboard.py`, `test_accounts_dir.py`).
- One test parametrize value corrected in `test_dashboard_review_fixes.py`:
  `mail_credentials_outcomes` result 2 now expects `"verification failed"` instead of
  `"verification is pending"` — when the server returns
  `r.error = "token saved, verification failed"`, the code displays `r.error`
  verbatim, not the i18n pending-fallback string.

## Upgrade

Existing installs: just replace the exe / run the updated gateway. The i18n system,
RTL CSS, and bundled font are additive — no config migration required. The language
choice persists in `localStorage`, so a returning user keeps their last-picked
language across restarts.
