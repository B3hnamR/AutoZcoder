# AutoZCoder 2.0.7

Bundles everything since 2.0.1: the claim pass now walks both plan inventories,
signup can run without a slider drag, and the reported version finally matches
the binary.

## Claims

- The billing preview and `/marketing/touch` are read as separate inventories.
  Start Plan variants only appear in the preview; Global/Weekend Build cards
  only appear as marketing deliveries, and their `plan_id` rotates per drop, so
  they are matched by name (`ZCODE GLOBAL BUILD`, `ZCODE WEEKEND BUILD`), never
  by a pinned id.
- A claim pass claims every offer it finds, not just the first grant, and an
  account that already holds a Start Plan is still checked for campaign cards:
  the buckets are independent.
- `data: null` (or no `data` at all) from the preview means "nothing offered",
  not a broken envelope. Accounts past the signup quota now report
  `no claimable plan` instead of a route problem.
- Marketing deliveries are impression-deduped per account: the first `seq=0`
  page returns the card and the next call is empty, so discovery and claim must
  stay in one pass.

## Signup

- New `mint` captcha mode: the bundled `captcha-mint` sidecar mints the Aliyun
  verify param with traceless verification in happy-dom (the same source the
  claim uses), and the generator sends the signup POST itself. No slider drag,
  no vision judge, no AI key. A failed mint falls back to the in-page solver.
- The signup captcha scene is fetched from `/api/v1/client/configs` per run
  instead of a hardcoded id, and the captured `captcha_verify_param` from the
  app's own POST is preferred over a rebuilt token.
- A signup POST that the app already sent is never re-sent (the duplicate
  tripped the per-email rate limit and half-created accounts).
- Captcha response parsing accepts both `T001`/`T006` and the lowercase
  `result` envelope.

## Environment and build

- Client version bumped to 3.18.0 across the plan, claim, and catalog paths;
  `x-client-timezone` is derived from the exit IP instead of a hardcoded value.
- The OAuth `client_id` / `redirect_uri` / `state` are parsed from the
  authorize URL instead of pinned constants.
- A proxy pinned in the generator options is exported to `ZAI_PROXY` for the
  child scripts; the API-route proxy no longer leaks into claim transport.
- Dashboard: an "After signup" switch for the claim pass, a "mint" captcha
  option, and a note explaining when campaign cards are actually claimable
  (Weekend Build = the Beijing weekend, Fri 19:30 - Sun 19:30 Tehran).
- The dashboard's `__version__` now tracks the shipped binary.
