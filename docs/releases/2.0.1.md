# AutoZCoder 2.0.1

A reliability and safety update for the 2.0.0 dashboard, gateway, account storage,
Auto Generate, native claim helper, and platform installers. Existing configuration
and packaged runtime-data locations remain unchanged.

## Gateway and model routing

- Fixed account concurrency slots remaining reserved when a request is cancelled
  while opening an upstream connection.
- Fixed quota-aware routing waiting on a saturated high-quota account instead of
  using an eligible account with free capacity.
- Separated future quota grants from currently usable balances. A pending grant
  no longer closes a model with live quota, and an expired bucket is not restored
  from its original entitlement.
- Fixed fallback after a model has been parked for a geographic restriction.
- Malformed SSE JSON, non-object events, and invalid UTF-8 now fail explicitly
  instead of silently dropping content and returning a successful answer.
- Fixed empty-object tool calls producing invalid empty-string OpenAI arguments.
- Usage and capture writes are drained before the database closes on shutdown.
- Stale upstream responses cannot apply authentication strikes, caps, cooling, or
  success transitions to credentials that have since been replaced.

## Accounts, credentials and settings

- Billing results are checked against the credential generation used for the
  request. A delayed rejection of an old token cannot kill a newly imported token
  or overwrite its fresh quota data.
- Unified snapshot ownership, filename allocation and atomic writes across
  generator registration, JWT import, device login and desktop credential import.
- Reimporting the same identity reuses its snapshot when the email label changes;
  duplicate selection uses credential freshness rather than expiry alone.
- Replaced shared pool-file temporary names and serialized API persistence/import
  transactions to avoid lost updates.
- Credential adoption preserves device, identity and refresh-token metadata;
  a newer token with no declared expiry is not automatically rejected as older.
- Re-login probes the canonical pooled account, and parallel login starts reuse
  the initializing flow.
- Settings are validated with the full startup schema before writing. Invalid
  values no longer save successfully and break the next startup.
- Relative TLS paths resolve against the configuration file's directory.

## Auto Generate and claim recovery

- Fixed workers launching after they were stopped or finalized, including the
  publication-to-process-start race.
- Completion waits for result handling and callbacks, not just process exit.
- Failed Resume preflight leaves progress recoverable after prerequisites are
  repaired.
- Cooldowns survive restart, duplicate counts are accurate, and long fixed-attempt
  runs can restore the identity count they are allowed to produce.
- Added durable run/attempt registration receipts and restart reconciliation to
  avoid losing qualification credit between account saving and progress updates.
- Qualification requires a real, currently spendable balance belonging to an
  accepted active Start Plan, not quota from another plan or an entitlement estimate.
- Automatic strict-proxy claims no longer silently select another proxy inside
  nested claim fallback.
- Successful recovery claims can register accounts missing from the running pool
  without requiring a gateway restart.

## Dashboard

- Aborting a Proxy request during navigation no longer overwrites the next page.
- Email configuration errors keep the form mounted and recover on retry without
  discarding entered credentials.
- Cloudflare credential actions distinguish rejected, saved, and saved-but-not-
  verified results instead of always announcing success.
- Cancelling or leaving a pending login prevents late windows, polling and reloads.
- Pending manual-generator option changes are flushed in order when leaving the
  page, with visible save errors rather than silently lost edits.
- Logs Clear hides existing records while allowing newer records to arrive.

## Native claim helper and proxy checks

- Fixed Happy DOM cookie insertion, expiry handling and outgoing cookie names
  against the locked dependency's actual cookie API.
- Applied an explicit route consistently to configuration, asynchronous and
  synchronous helper requests. SOCKS routes use a bounded, loopback-only CONNECT
  bridge; there is no silent direct fallback or new public listener.
- Added exclusive ownership for in-process solves and reusable windows.
- Added incremental response byte limits, deadlines and cancellation. Child stdout
  and stderr have independent byte ceilings and bounded owned-process cleanup.
- Invalid HTTP/JSON/business envelopes return structured failures instead of
  escaping as unrelated exceptions.
- Mixed claim outcomes no longer become a false report that every offer is
  unavailable.
- Proxy verification rejects failed captcha-host responses, unexpected redirects,
  oversized bodies and indefinitely trickling responses.

## Windows and Linux maintenance

- Windows terminal server-startup failures exit instead of leaving an unusable
  fallback process alive.
- The Windows updater now requires a per-launch nonce health acknowledgement from
  the replacement within 60 seconds. Process survival alone is not accepted.
  The check supports explicit interface binds and pins configured TLS certificates.
- Linux dependency/browser/npm maintenance runs as the tooling user, not through
  a service-writable interpreter executing as root. Private Node binaries remain
  root-owned.
- Certificate changes stage and validate the replacement, retain the working pair
  on failure, and restore configuration/renewal policy if activation fails.
- TLS mode survives reinstall, including domain, self-signed and loopback-only
  modes. Renewal targets the active certificate.
- Install, update, certificate changes and uninstall share a mutation lock.
- ARM64 source installs can reach the supported source-build path; release binaries
  still enforce their architecture and libc requirements.
- Non-root manager use reports a clear sudo requirement; help remains accessible.

## Upgrade and validation notes

- Back up private account/configuration/database data and stop work before upgrading.
  Neither a health check nor the regression suite guarantees provider signup,
  CAPTCHA, plan-claim or inference acceptance.
- The JavaScript in-process fallback cannot forcibly preempt synchronous guest CPU.
  The external claim subprocess has bounded runtime and process cleanup.
- Windows and Linux regression suites, offline sidecar tests, local process/network
  fixtures and the packaged Windows startup smoke check are used to validate this
  release candidate. Live ACME issuance and production-provider workflows require
  separate operator acceptance tests.

## Linux VPS install

After `v2.0.1` is published, install over SSH with:

```bash
curl -fsSL https://raw.githubusercontent.com/B3hnamR/AutoZcoder/v2.0.1/install-linux.sh | sudo bash -s -- install
```

Review the versioned installer first if your policy requires it. The prebuilt Linux
binary requires x86_64, glibc 2.35 or newer, and compatible system libraries
(Ubuntu 22.04 build baseline). Older glibc, musl/Alpine and other architectures
require a compatible source build. Start with 2 reliable vCPUs and 4 GB RAM for
comfortable one-browser generation.
